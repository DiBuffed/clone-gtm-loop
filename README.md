# YoriGO Agentic GTM Loop

**제품 주소와 실제 앱 시연에서 시작해, 공개 고객 신호 → 타깃 판정 → 가상 페르소나 → AI 리액션 영상 → 시연·CTA 합성 → Instagram 배포 → 실제 활성화 → 다음 조사를 연결합니다.**

- 제품: [요리GO](https://yorigo.kr/) — SNS 레시피 링크를 재료 정리와 장보기로 연결하는 앱
- 행사: Clone Loop Day in Seoul / 2026-10-24
- 7일 평가 마감: **2026-10-31 토요일 18:00 Asia/Seoul (09:00 UTC)**
- 실행 화면: **`/gtm/loop`**. 노드를 클릭하면 검색어, 원문, YES/NO/UNKNOWN 판정, 페르소나 이유, 프롬프트, 생성 파일, 게시 ID, 성과, 다음 결정을 확인합니다.
- 원본 제작 도구: UGC-Z. 이 저장소는 해커톤의 GTM 운영·평가용 실행 코드와 방법론을 독립적으로 보관합니다.

기존 가입자·활성 사용자 전체 수의 시작 기준선은 **아직 연결·확인하지 않았습니다**. 0이라고 가정하지 않습니다.
위 신규 활성 목표는 추적 가능한 캠페인 유입 코호트 기준이며, 대조군 없는 순증 인과효과라고 주장하지 않습니다.
목표 변경 시 원래 값·변경 시각·이유를 함께 남깁니다. 결과에 맞춰 목표를 덮어쓰지 않습니다.

## 왜 이 고객과 이 형식인가

첫 고객 가설은 **SNS 요리 영상을 저장하지만 다시 찾고 재료를 정리하는 번거로움 때문에 실제 요리로 옮기지 못하는 한국어 사용자**입니다.
연령/성별을 먼저 추정하지 않고 최근에 공개적으로 표현한 불편으로 적합성을 판단합니다.

AI 인물은 실제 이용자인 척하는 후기가 아니라 **창작된 성인 진행자**입니다. 표정으로 관심을 끄는 3초 리액션에
고객의 불편을 훅 자막으로 얹고, 뒤에는 실제 요리고 시연과 CTA를 붙입니다. 같은 고객에서 훅을 비교할 때는
진행자와 시연을 재사용해 변수를 줄이고 생성 비용을 아낍니다.

## 실제 루프

1. **제품 이해** — 허용한 제품 도메인에서 확인 가능한 기능과 원문 근거를 저장.
2. **고객 신호 조사** — Tavily로 공개 원문 검색. 검색어·조회 시각·게시 날짜·URL·본문 저장.
3. **바이너리 판정** — OpenAI가 짧은 정확 인용을 추출하고, 코드가 원문 일치·날짜·중복·제품 기능 연결을 검사.
   날짜가 없으면 UNKNOWN. 근거가 부족하면 최대 세 차례 검색을 바꾸고, 계속 부족하면 중단.
4. **타깃·페르소나 설계** — 통과 원문과 검증한 제품 기능에 연결된 고객 정의·가상 인물·훅·CTA를 Structured Outputs로 생성.
   인물의 외모는 창작 설정이며 원문 작성자의 인구통계라고 주장하지 않음.
5. **페르소나 생성** — Higgsfield Soul 이미지 생성 → 원격 작업 ID 보존 → 자체 저장.
6. **리액션 영상 생성** — 동일 인물의 이미지로 무음 리액션 영상 생성 → 3초 사용.
7. **앱 시연 합성** — FFmpeg가 실제 녹화·음성·훅·CTA·AI 진행자 표시를 최종 MP4로 합성·검사.
8. **배포** — 검토 후 게시 또는 명시적으로 선택한 자동 게시. Instagram 컨테이너·게시 ID·원문 링크 보존.
9. **트랙션 관측** — 게시 후 최소 60분, 방문 10건 기준으로 관찰. 앱의 실제 생성/저장 이벤트와 연결.
10. **학습·재실행** — 방문이 적으면 기다림. 방문은 있지만 활성화가 없으면 첫 사용 경로 점검.
    활성 고객이 관측되면 같은 고객·페르소나에서 새 근거와 훅을 설계하고 다음 조사로 연결.

조회수가 높은 영상만을 자동으로 승자로 정하지 않습니다. 작은 표본에서는 탐색 결과로 표시합니다.
7일 재사용은 관찰이 끝난 사용자만 분모에 넣고, 미성숙 코호트는 대기 상태로 남깁니다.

## 지금 실행할 수 있는 것과 연결이 필요한 것

| 영역 | 구현·검증 |
|---|---|
| 실행 화면 / 단계별 근거·로그 / 모바일 | 구현, 브라우저 검증 |
| 제품 읽기·검색·전략 / 페르소나·영상 API / 배포·관측·재실행 | 어댑터와 2라운드 계약 테스트 구현 |
| 실제 업로드 → 워커 → FFmpeg → MP4 → 다운로드·검토 | 실제 파일로 검증 |
| 서명 미디어 / 세션 / 암호화 연결 키 / 내구성 큐·lease | 구현·테스트 |
| 실제 검색·AI 공급자 과금·Instagram 프로 계정 게시 | **운영 키·계정 연결 후 라이브 검증 필요** |
| 실제 신규 고객·매출 | **아직 관측·주장하지 않음** |

테스트 리플레이에는 `mode=test`가 표시됩니다. 테스트 응답의 조회·활성 숫자는 실제 고객 트랙션에 합산하지 않습니다.
테스트 실행은 라이브 워커에서 재개하거나 자동 게시할 수 없습니다.

## 실행 — 별도 지원 서버 없이 운영 가능

Node.js 24+, FFmpeg/ffprobe, 한글 글꼴이 필요합니다. 로컬 PC 또는 직접 준비한 서버에서 웹과 워커를 계속 실행합니다.

```bash
npm ci
cp .env.example .env.local
# GTM_ADMIN_TOKEN, GTM_EVENTS_TOKEN에 각각 다른 32자 이상 값을 설정
# GTM_FONT_PATH를 실제 한글 글꼴 경로로 설정
npm run dev
# 두 번째 터미널
npm run gtm:worker
```

`http://localhost:3000/gtm/loop` 접속 → 운영 키 로그인 → **연결 설정** → 제품 주소·시연 입력 → 라이브 루프 시작.
연결 키는 서버에서 암호화하며 브라우저 localStorage에 저장하지 않습니다.
Tavily, OpenAI 키 및 사용 가능한 Structured Outputs 모델, Higgsfield API 키, Instagram 프로 계정 토큰/ID/Graph 버전을 연결합니다.
Higgsfield 웹 구독 크레딧과 API 잔액은 별개입니다.

생성 공급자와 Instagram이 미디어를 가져가려면 `GTM_PUBLIC_URL`에 접근 가능한 HTTPS origin이 필요합니다.
호스팅/터널은 본인 환경에서 준비해야 합니다. GitHub Pages만으로는 FFmpeg·워커를 실행할 수 없습니다.
Docker는 선택 사항이며 [배포 설정](compose.yaml)을 제공합니다. 행사 주최 측 컨테이너 지원을 전제로 하지 않습니다.

### 7일 실행 명령

```bash
# 운영·이벤트 키 준비, 실제 시연 파일 등록 (키 값은 출력하지 않음)
npm run seven-day:prepare -- --demo-path /absolute/path/app-demo.mov
# UI 로그인 후 공급자/배포 계정을 연결하고 웹을 켠 상태에서:
npm run seven-day:run
# 현재 목표 대비 성과와 연결 한계 확인:
npm run seven-day:status
```

`seven-day:run`은 마감까지 워커와 날짜별 집계를 유지하고, 이전 루프가 완료된 뒤 다음 한국 날짜에 새 루트를 조사합니다.
연결·검토·표본 대기 중인 루프, 운영자가 정지한 루프, 활성화 병목이 있는 루프를 건너뛰어 새 비용을 쓰지 않습니다.
마감 이후 새 생성/게시를 차단합니다. PC·프로세스가 계속 실행돼야 하며, 이 명령이 서버 자원을 제공하는 것은 아닙니다.
`/gtm/results`에서 목표 대비 실적·기준선 미확인·외부 대기·검증된 매출·재사용 분모를 확인합니다.
