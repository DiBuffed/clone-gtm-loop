# 구현 경계와 다음 단계

## 현재 결정

두 명이 협업하는 UGC-Z의 첫 결과물은 전체 자동화 서비스가 아닌 프런트엔드 뼈대다. 최신 대화의 역할 분담을 우선한다.

| 담당       | 현재 의도                            | 경계                                               |
| ---------- | ------------------------------------ | -------------------------------------------------- |
| 코파운더   | 앱 설명·타겟·후킹 입력으로 Hook 제작 | Higgsfield 등 외부 서비스 → Hook 자산              |
| 사용자     | 폰 기반 앱 시연·자막 편집 자동화     | Claude Code/MCP로 개발하는 편집 실행기 → Demo 자산 |
| 공동, 이후 | 두 결과물 합성                       | Composer → 최종 MP4                                |
| 이후       | 계정·게시·최종 리포트                | 별도 연동 단계                                     |

Claude Code는 개발·자동화 도구이며, 서비스의 상시 실행 환경으로 자동 제공되는 것이 아니다. 실제 편집 실행기는 선택한 MCP 편집 도구 또는 FFmpeg 등으로 따로 연결한다.

Higgsfield는 공식 비동기 REST API와 TypeScript/Python SDK, Claude Code·Cursor용 MCP 서버를 제공한다(2026-09 확인). 이 저장소는 아직 연동하지 않으며 동작을 가정하지 않는다. 구현 전에 반영할 제약:

- 출력 파일은 약 7일만 보관되므로 자체 스토리지로 즉시 복사하는 단계와 `expires_at` 추적이 필요하다. 누락 시 자산이 소실되고 재생성은 재과금이다.
- 과금은 구독과 분리된 선불 USD 잔액이므로, 잔액 소진이 실패가 아닌 대기로 나타나 감지가 어렵다. 잔액 모니터링이 운영 항목이다.
- 키당 동시 요청 기본 한도 20건이 고객별 동시 실행 제한과 직결된다.
- 공식 문서와 마케팅 페이지의 base URL 안내가 다르다. 착수 시 실제 엔드포인트를 코드로 검증한다.

## 화면

고객: 대시보드 / 콘텐츠 / 게시 일정 / 앱 프로필 / 설정.
운영: 제작 관리 / 시연 편집 / 자산 검수 / 연동 현황.

시연 편집은 Demo 엔진(`tools/autocut`)의 사람 쪽 창구다. 지금 autocut은 로컬 CLI라서
화면은 그 결과 파일을 브라우저에서 열어 검토하고, 고친 파일을 다시 CLI에 넘긴다.
파일은 업로드하지 않는다. 화면 위쪽의 흐름표가 어느 단계가 자동이고 어느 단계에
사람이 붙는지를 보여 준다. 스토리지와 워커가 생기면 "파일 열기"가 작업 목록으로,
"내려받기·명령 복사"가 "드래프트 만들기" 버튼으로 바뀌고, 사람 칸은 컷 검토와
CapCut 마무리만 남는 것이 목표다.

게시 일정·성과는 미래 화면을 검토하기 위한 샘플이며 이번 버전에 게시 엔진이 구현된 것은 아니다. 계정 생성, 폰 계정 운영, DM, 워밍업은 구현 범위 밖이다.

랜딩 페이지는 이 문서의 순서와 다르게, 완성형인 **성장 루프 전체**를 제품으로
제시한다. 만들고·올리고·보고·다시 하는 한 바퀴가 제품의 정의이기 때문이다.
다만 구현된 범위는 3번(합성·다운로드)까지이고 게시·측정은 8번이다. 랜딩에서 이
간극은 히어로·FAQ·CTA 주의문 세 곳으로만 밝힌다(2026-09-21에 "지금 어디까지
되나요" 섹션을 뺐다). 게시와 측정을 구현하면 그 주의문들을 현재형으로 바꾼다.

계정 운영은 플랫폼 약관과 직결된다. 자동 게시는 각 플랫폼이 허용하는 공식 API
범위를 확인한 뒤에만 붙인다. 기기 지문을 흉내 내거나 실제 기기에서 사람처럼
동작시키는 방식은 검토 대상이 아니다.

## 상태 소유권

- URL: 날짜와 계정 필터
- 폼: 컴포넌트의 로컬 초안
- 데모 공유 상태: DemoProvider + 검증된 localStorage
- 모달·탭·메뉴: 컴포넌트 로컬 상태
- 실제 서비스에서 영구 상태: PostgreSQL로 교체

현재 API가 없으므로 TanStack Query, Redux, Zustand는 설치하지 않는다. 서버 폴링이 생길 때 도입을 결정한다. localStorage 파싱에는 Zod를 적용한다. 데이터 형식이 틀리면 안전한 초기값과 오류 안내를 사용한다. 여러 탭 동시 편집 충돌은 현재 지원하지 않는다.

## 다음 구현 순서

1. 인증 및 조직 멤버십 모델. 고객/내부 역할은 서버에서 검증.
2. PostgreSQL에 앱 프로필과 요청을 저장. 현재 localStorage 저장 어댑터 대체.
3. Private 스토리지와 업로드 검증. Hook/Demo를 수동 등록해도 실제 한 쌍으로 검증.
4. 각 엔진과 `src/lib/contracts.ts`의 자산 계약 합의. 음악 포함 여부/자막 분리 확인.
5. 외부 서비스별 submit/status/result 어댑터. 타임아웃, 재시도, 공급자 작업 ID 저장.
6. 웹 요청과 별개인 워커·작업 큐. 진행 상황은 서버 조회로 표시.
7. Composer, 실제 미리보기, 승인, 다운로드.
8. 허용된 API 범위를 검증한 뒤 게시·측정. 실험은 충분한 측정 데이터 이후.
9. 성장 루프 검증 후 크리에이터 마켓플레이스.

## 불변 조건

- 요청에는 앱 정보·타겟·후킹의 스냅샷을 보존한다.
- Hook과 Demo 상태는 별개다. 둘 다 준비되기 전 Compose 불가.
- 생성 재시도로 이전 자산을 덮어쓰지 않는다. 새 버전과 ID 부여.
- 승인과 게시는 별개. 승인했다고 자동 게시됐다고 표시하지 않는다.
- 비용 발생 작업은 서버 측 한도와 idempotency key 필요.
- 큐의 중복 방지 기능만으로 외부 API의 중복 과금을 막았다고 가정하지 않는다.
- 유료 작업은 브라우저 종료에도 유지되는 내구성 있는 상태로 관리한다.
- 성과 원인 분석은 인과관계 확정이 아닌 관찰과 가설로 표시한다.

## 디자인

흰 캔버스(`--canvas #ffffff`)에 차가운 무채색 회색, 강조색은 시안 하나다. 시안은 버튼 채움
(`--accent #1cc9b2`, 글자는 짙은 `--accent-ink`)과 글자(`--accent-text #0a7f71`, 흰 바탕 대비
확보) 두 가지로 쓴다. 로그 콘솔과 영상 미리보기 틀만 어둡다. 상태색(경고 주황·위험 코랄)과
타임라인 클립 색(남김 시안·배속 주황·잘림 코랄 빗금)은 의미가 있을 때만 쓴다. 색은 `globals.css` 맨 위
`:root` 토큰으로만 쓰고, 랜딩은 같은 값의 `--ld-*` 토큰을 쓴다. 한글은 Pretendard, 수치와
타임코드는 Geist Mono(고정폭 숫자)다.

참고한 기준: Taste skill의 밀집형 제품 UI 규칙(작은 여백, 무채색 하나 + 강조색 하나,
그라디언트·보라색 금지, 모서리 8px 이하, 수치는 고정폭), Vercel Web Interface Guidelines
(`color-scheme`, `theme-color`, 포커스 표시, 모션 줄이기 존중), awesome-design-md의
Runway·Linear 디자인 시스템(차가운 회색 글자, 절제된 강조 하나).

랜딩 문구의 콘셉트는 "앱을 UGC 영상으로 자동 마케팅하는 서비스"다. 대상은 앱을 만드는 팀이고,
UGC(실제 사용자가 써보고 올린 것 같은 짧은 영상)는 첫 화면과 FAQ에서 설명한다. 소개 섹션은
"앱을 만드는 일과 알리는 일은 다릅니다" 문구를 쓴다(사용자가 고른 초기 문구).

고객에게는 요청과 결과를, 운영자에게는 단계와 오류를 보여준다. 리스트 영상 자동 재생 없음.
썸네일은 외부 이미지 없이 CSS로 제작했다(종류별로 한쪽에서 번지는 색 조명).

## 유지보수

현재 공통 Workspace 컴포넌트 안의 화면 함수는 첫 UI 검토를 위한 작은 수직 단위다. 실제 API를 연결할 때 profile/content/operations 기능 디렉터리로 분리하고, 기존 도메인 함수와 계약은 유지한다. 기능별 백엔드 서비스 분리나 Kubernetes는 지금 필요하지 않다.
