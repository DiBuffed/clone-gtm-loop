# 서비스 공개 전 체크리스트

이 프로젝트는 인증 없는 프런트엔드 프로토타입이다. 보안 완료된 SaaS로 배포해서는 안 된다. UI의 `/admin` 메뉴 숨김이나 경로 분리는 인가가 아니다.

## 구현된 기본 조치

- TypeScript strict, Zod 입력/저장 데이터 검증
- 기본 React 텍스트 escaping; 사용자 HTML 삽입 없음
- 클라이언트에 공급자 키나 계정 토큰 없음
- 파일 업로드·원격 URL fetch·코드 실행 기능 없음
- nosniff, frame deny, referrer, permissions 헤더
- 데모 상태·실제 기능 미연결 표시

## 로컬 자동 편집 실행기 (`/api/autocut/*`)

관리자 화면의 편집실은 업로드한 영상을 받아 이 컴퓨터에서 `tools/autocut`(Python)을 실행하고
CapCut을 연다. 인증이 없으므로 아래 조건에서만 켠다.

- `.env.local`에 `AUTOCUT_LOCAL=1`이 있을 때만 동작한다. 없으면 모든 경로가 404다.
- `Host`와 `X-Forwarded-For`가 루프백이 아니면 403이다. 두 헤더는 클라이언트가 꾸밀 수 있으므로
  이것만으로 네트워크 접근을 막았다고 보지 않는다. 편집실은 `npm run studio`(127.0.0.1에만
  바인딩)로 띄운다. `npm run dev`는 0.0.0.0에 바인딩하므로 같은 네트워크의 기기가 닿는다.
- 영상 확장자만 받고 파일 이름은 정리해서 저장하며 2GB에서 끊는다. Python은 셸 없이 고정된
  인자 목록으로 실행한다. 받는 파일은 정해진 이름(자막·계획·결과·원본 영상)만 내준다.
- 공개 배포에서는 켜지 않는다. 서비스로 열려면 인증·조직 권한 검사와 워커 분리가 먼저다.

## 인증/권한

- [ ] 검증된 인증 공급자 및 서버 세션 검증
- [ ] 모든 읽기/변경 요청에 조직 멤버십 확인
- [ ] 고객 조직 역할과 UGC-Z 내부 역할 분리
- [ ] 모든 운영 API에 내부 역할 확인; 원칙적으로 기본 거부
- [ ] 다른 조직의 자산·요청 ID로 접근하는 부정 테스트
- [ ] HttpOnly/Secure 세션 쿠키, 세션 만료·로그아웃, CSRF 방어
- [ ] 개인정보를 localStorage에 저장하지 않도록 영구 저장 교체

## 미디어/AI

- [ ] Private bucket, 짧은 만료의 presigned URL, 업로드 완료 검증
- [ ] 크기/유형/signature/미디어 길이/해상도 제한; MIME 헤더만 신뢰하지 않기
- [ ] 고유 객체 키, 격리된 미디어 처리, CPU·메모리·시간 제한
- [ ] FFmpeg는 argument 배열로 실행. 사용자 입력을 shell 명령으로 조합 금지
- [ ] 원격 URL 입력은 SSRF 검사. 내부 주소와 리디렉션 우회 차단
- [ ] 공급자 키는 서버에만 보관; 로그에서 키·토큰·개인정보 마스킹
- [ ] 고객별 생성 예산, rate limit, 동시 실행 제한, 중복 과금 방지
- [ ] 얼굴·음성·음악 사용 권리, 동의 기록, 삭제·보존 정책 검토
- [ ] 외부 webhook 서명·재전송 검증, 중복 이벤트 처리

## 운영
