## 매일 같은 판단 순서

1. 워커 heartbeat, 오류·외부 대기·중복 요청 여부 확인.
2. 최근 7일의 공개 고객 불편 근거를 확인. UNKNOWN을 YES로 바꾸지 않음.
3. 실제 배포와 유입 링크 연결을 확인. 게시 승인과 실제 게시 완료를 구분.
4. 앱 백엔드에서 신규·적합·테스트 여부와 이벤트를 받았는지 확인.
5. 관측 기간과 방문 수가 부족하면 추가 과금·새 실험을 멈추고 대기.
6. 바꿀 변수 하나와 이유를 결정. 실제 다음 실행이 있어야 개선 사이클로 셈.
7. `reports/YYYY-MM-DD.json`과 실행 내보내기를 보관. 값이 없으면 null과 이유 기록.

## 운영 장소

주최 측 서버를 기대하지 않습니다. 본인 PC 또는 본인 서버에서 웹과 `npm run gtm:worker`를 유지합니다.
서비스가 꺼진 기간은 실행했다고 주장하지 않습니다. SQLite와 미디어 디렉터리를 함께 백업합니다.
실제 연결 키·게시 계정·공개 HTTPS·요리고 앱 이벤트가 없으면 해당 단계는 blocked이며, 리플레이를 실제 운영 실적으로 제출하지 않습니다.
