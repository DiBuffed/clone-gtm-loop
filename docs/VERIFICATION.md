### 제거한 섹션 — 지금 어디까지 되나요

"되는 것과, 준비 중인 것." 섹션을 랜딩에서 뺐다. 미출시 기능을 구현된 것처럼
주장하지 않으려고 두었던 장치라, 걷어낸 뒤에도 그 역할을 하는 문구가 남아 있는지
확인했다.

- 히어로 주의문 — 로그인과 결제는 준비 중
- FAQ "영상을 만들고 올리는 걸 다 해주나요?" — 자동 업로드와 조회수 수집은 준비 중
- CTA 주의문 — 실제 AI 생성과 자동 업로드는 아직 실행되지 않음
- 푸터 — "샘플 데이터 · 실제 영상 아님" (목업의 조회수·계정이 실제 기록이 아님)

함께 정리한 것: `liveNow` `planned` 배열, `.ld-status*` 스타일 12개 규칙,
`ScrollReveal` 관찰 목록의 두 셀렉터, 섹션을 가리키던 FAQ 문장,
그리고 이 섹션만 검사하던 E2E 시나리오(`landing states what is live and what is not`).

E2E 시나리오 — 제품 4개:

- 프로필 저장 후 새로고침 유지, 요청 생성 → 운영 콘솔 반영
- URL 필터, 빈 상태, 콘텐츠 상세 검토
- 모바일 내비게이션, 가로 오버플로 없음
- 손상된 저장소 복구

### 발견한 결함 — 죽은 셀렉터가 모바일 버거를 화면 밖으로 밀어냈다

`.ld-nav-actions .ld-btn-ghost`를 숨기라는 규칙이 있었지만, 실제 내비게이션에는
`ld-btn-quiet`(로그인)과 `ld-btn-primary`(무료로 시작하기)만 있었다. 규칙이 한 번도
적용되지 않아 좁은 화면에서 버튼과 버거가 한 줄에 들어가지 못했고, 버거가 390px
화면에서 `358..396`에 놓여 6px가 잘렸다.

`.landing`에 걸린 `overflow-x: hidden`이 넘침을 `scrollWidth`에서 지워버려서
기존 오버플로 검사는 통과했다. 그래서 내비 요소의 좌표를 직접 재는 검사를
추가했다(`clipped` 배열이 비어 있어야 통과). 셀렉터는 `.ld-btn-primary`로 고쳤다.

### 발견한 결함 — 등장 효과가 내용을 영영 투명하게 남겼다

스크롤 등장 효과를 `IntersectionObserver`로 만들었더니, 상단 메뉴의 앵커 링크
(`#how`, `#faq`)나 빠른 휠처럼 화면을 건너뛰는 이동에서 관측 시점을 놓친 요소가
`ld-reveal`(=`opacity: 0`) 상태로 남았다. 실측에서 21개 중 **9개**가 끝내 `opacity 0`
이었고, 그 구간은 스크롤을 되돌리기 전까지 아무 내용도 보이지 않았다.

`ScrollReveal`을 스크롤 처리 기반으로 바꿨다. 화면 밖 요소만 숨기고,
`requestAnimationFrame`으로 묶은 처리에서 `top < 화면 높이 * 0.88`인 것을 모두
되돌린다. 화면 위로 지나간 요소(`top < 0`)도 같은 조건에 걸리므로 건너뛰기가
결과에 영향을 주지 않는다. 첫 화면에 걸친 요소는 아예 숨기지 않는다.

`검사: scroll reveal never strands a section invisible` — 앵커로 건너뛴 뒤 300px씩
훑고, `opacity < 1`로 남은 요소가 없어야 통과한다.

### 발견한 결함 — 활자 크기가 요소마다 눈대중으로 정해져 있었다

랜딩 한 장에 `9.5` `10` `11.5` `12` `12.5` `13` `13.5` `14` `14.5` `15` `16` `16.5`
`17` `18` `19` `22` `30`이 섞여 있었고(21종), h2가 `clamp(26px,3vw,38px)`과
`clamp(27px,3.5vw,42px)` 두 가지로 갈라져 있었다. 모서리도 `2` `6` `8` `9` `12` `16`
`18` `999` `50%`(9종)였다. 같은 역할이 다른 값을 쓰면 화면이 정돈되지 않는다.

역할 기준 토큰으로 바꿨다. 활자 12종(`--ld-t-nano` ~ `--ld-t-h1`, 루트 `16px` 제외),
모서리 4종(`--ld-r-sm` `--ld-r-md` `--ld-r-lg` `--ld-r-full`, 세그먼트 안쪽은
`calc(var(--ld-r-sm) - 3px)`). 함께 정리한 것:

- `.ld-plan-note`에 폭 제한이 없어 한 줄이 1052px(약 81자)까지 늘어났다 → `max-width: 620px`
- `.ld-hero-note`가 폭 제한 없이 가운데 정렬돼 있었다 → `max-width: 520px`
- `.landing`에 `overflow-x: hidden`과 `clip`이 중복 선언돼 있었다 → 제거
- `.ld-plan-desc`의 `min-height: 42px`는 두 줄 높이 계산값임을 주석으로 남겼다

### 발견한 환경 문제 — 로컬 E2E는 프로덕션 빌드를 서빙한다

`playwright.config.ts`의 webServer는 `npm run start`를 실행한다. 즉 `.next`에
있는 **마지막 빌드**를 그대로 서빙하며, 다시 빌드하지 않는다. 그래서 소스를
고친 뒤 `npm run build` 없이 `npm run test:e2e`만 돌리면 예전 화면을 검사하고
통과해버린다. 실제로 히어로를 회전형으로 바꾼 뒤 빌드를 건너뛰어 새 요소를
찾지 못하고 1개가 실패했다. 소스를 고쳤으면 항상 build를 먼저 돌린다.
CI는 build 단계가 e2e 앞에 있어 해당하지 않는다.

### 발견한 환경 문제 — dev 서버와 E2E의 출처 불일치

Playwright는 `127.0.0.1:3000`으로 접속하는데, Next.js 16 dev 서버는 기본적으로
`localhost`만 허용하고 `127.0.0.1`은 교차 출처로 차단한다. 그래서 dev 서버를
띄운 채 `npm run test:e2e`를 돌리면 dev 리소스가 막혀 8개 중 6개가 실패했다.

`next.config.ts`에 `allowedDevOrigins: ["127.0.0.1"]`를 추가해 해결했다.
개발 모드에서만 적용되므로 프로덕션과 CI에는 영향이 없다.

이 문제는 랜딩 변경과 무관하게 원래부터 있던 것이다. 제품 화면 테스트도 같이
실패해서 원인이 랜딩이 아님을 알 수 있었다.

한 가지 더: dev 서버를 갓 띄운 직후에는 라우트를 처음 요청할 때 컴파일하느라
30초 타임아웃을 넘길 수 있다. 한 번 더 돌리면 통과한다. CI는 프로덕션 서버를
쓰므로 해당하지 않는다.
